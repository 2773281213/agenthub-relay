01

skill 离不开手写的 MCP 配置

路由 skill 只会调用 relay_* MCP 工具，派发步骤只写在 MCP 处理函数里，CLI 不能派发；除 Claude Code 插件外，每家规划者都得先手工注册 MCP 服务才能用。

证据有力 · 依赖：进程内 · 业务影响：Codex、DeepSeek Harness、Antigravity 的用户要按文档逐家写 MCP 配置，dsh 的配置文件位置连文档都没写；配不好 skill 就用不了。等待也受 MCP 客户端超时限制，只能 50 秒一轮。

  1. ①
    skill 绑死 MCP已观察

    SKILL.md 的描述写明通过 relay_* MCP 工具工作，并且只在这些工具可用时触发；规划者没配好 MCP，skill 就没有可用的动作。Codex 要 codex mcp add，dsh 的配置文件位置文档里没有写，安装负担落在每个用户身上。

  2. ②
    CLI 不能派发已观察

    CLI 只有 mcp、worker、doctor、status；派发、等待、取结果、apply 的步骤只写在 MCP 处理函数里。能跑 shell 的 agent 本可以直接调用命令，现在却必须经过 MCP。

  3. ③
    等待受超时限制已观察

    relay_wait 每次最多 50 秒，是为了躲开 Codex 默认 60 秒的工具超时；这是 MCP 客户端的限制漏进了接口。命令行等待可以按 shell 的超时设置更长的时长。

调用方现在要记住：

  1. 先写 MCP 配置
  2. 各家配置位置
  3. relay_* 工具名
  4. 50 秒轮询等待

收拢之后只剩：

  1. 装 skill
  2. 跑脚本

方案

把派发、等待、取结果、apply、discard、cancel 收进 jobs.mjs；CLI 补齐这些命令并输出与 relay_status 相同的 JSON；skill 包自带脚本，SKILL.md 改为先用 CLI、MCP 可选。

删除测试 · 收窄

MCP 服务不删：Claude Code 插件和偏好工具调用的规划者仍用它；它退化为 jobs.mjs 之上的薄层，复杂度集中到生命周期模块，而不是转给调用方。

不改变

  • relay_* 工具的名称与参数
  • job.json 的字段
  • Claude Code 插件与 mod 的行为
  • 零运行时依赖

收益

  • 杠杆能跑 shell 的规划者装上 skill 就能用，不写 MCP 配置
  • 局部性派发顺序与清理只写在 jobs.mjs 一处
  • 可测性CLI 全流程可以直接用 node --test 驱动

迁移代价

中等：新增 jobs.mjs（约 150 行从 tools.mjs 移入）、6 个 CLI 命令及测试、SKILL.md 改写；长任务描述要走文件或 stdin，避开命令行长度与转义问题。

通过 Interface 验证

  • 用 CLI 完成 dispatch→wait→result→apply，结果与 MCP 路径的记录一致
  • AGENTHUB_RELAY_ROLE=executor 时 CLI dispatch 同样被拒
  • 现有 49 项 node 测试与 10 项 mod 测试不改断言仍通过
02

每家规划者都要照文档手工安装

安装说明按 Claude Code、Codex、dsh、Antigravity 分四段，各写一遍复制 skill、注册 MCP 的步骤；只有 Claude Code 插件能自动接线。

值得探索 · 依赖：可用本地替身 · 业务影响：换一个规划者就要重读一段文档、手改一个配置文件，路径写错或漏装 skill 时没有任何提示；也容易在共享目录和专属目录各装一份，造成重名。

图号02 / 现状批注3依据源码 4 处

同一套安装步骤按四家规划者各写一遍，用户逐段照做，装错也没有提示。

  1. ①
    同一步骤写四遍已观察

    复制 skill、注册 MCP 服务这两步，在文档里按四家规划者各写一遍，各自的路径和命令都不同；每多接一家，用户就多一段手工步骤。

  2. ②
    没有安装命令已观察

    仓库没有安装或自检命令；doctor 只报告执行者是否装好，不检查 skill 和规划者的配置，装错时没有提示。

  3. ③
    可能重复安装待验证

    dsh 同时读取 ~/.dsh/skills 和 ~/.agents/skills；照文档装进 .dsh/skills 后，若再用第三方 CLI 装进 ~/.agents/skills，会出现两个同名 skill。这一点依据 Birdview 安装文档推断，没有在真实 dsh 上验证。

调用方现在要记住：

  1. 每家的配置路径
  2. MCP 命令写法
  3. skill 放哪个目录
  4. 避免重复安装
