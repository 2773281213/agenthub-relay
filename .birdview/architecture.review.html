01

保活所依赖的状态格式没有契约

mod 每分钟读 relay_status 来决定保活和唤醒，但它读到的字段由 hub 的 summarize() 决定，mod 里另抄了一份类型，解析后直接断言，测试只喂手写桩。

证据有力 · 依赖：可用本地替身 · 业务影响：hub 改一个字段名（如 resultFetched），node 测试和 mod 测试都会照样通过，而保活和唤醒会静默失效：等待中的 Claude Code 缓存过期，任务结束也不会被叫醒。

字段在 hub 里定义、在 mod 里重抄，中间只有一段 JSON 文本，没有任何一方检查两边是否一致。

  1. ①
    字段定义两份已观察

    RelayJob 逐个重抄 summarize() 返回的 id、status、integration、resultFetched 等字段；两份定义分别在 Node 模块和 mod 里，没有共同来源。

  2. ②
    没有输出契约已观察

    MCP 结果只有一段 JSON 文本，relay_status 没有声明 outputSchema；mod 解析后用 as 断言类型，字段缺失或改名时不会报错，只会让判定悄悄变成“没有任务”。

  3. ③
    测试只测手写桩已观察

    mod 测试的 relay_status 桩按 RelayJob 手写，从不使用服务器的真实输出；hub 的 node 测试又不知道 mod 依赖哪些字段，两边各自通过也证明不了它们对得上。

调用方现在要记住：

  1. 字段名逐个对齐
  2. JSON 包在 text 里
  3. integration 取值
  4. resultFetched

收拢之后只剩：

  1. 读声明的输出

mod 测试用手写的状态桩

方案

为 relay_status 声明 outputSchema 并返回 structuredContent；加一条 node 契约测试，用真实服务输出核对 mod 依赖的字段，mod 读结构化结果并在缺字段时报错。

删除测试 · 保留

mod 在没有 Node 的环境里运行，只能经 MCP 读状态，这层边界不能删；要补的是边界上的契约，而不是去掉一层。

不改变

  • relay_status 的文本输出保持不变，旧客户端照常可读
  • mod 的保活判定规则
  • job.json 的字段

收益

  • 接缝状态格式只在 schema 一处声明
  • 可测性契约测试用真实输出，字段改名立刻失败
  • 杠杆Codex 等规划者也能直接读结构化状态

迁移代价

小：一个 schema、tools.mjs 与 mcp.mjs 各几行、一条契约测试、mod 改读 structuredContent；不改工具名与参数。

通过 Interface 验证

  • relay_status 的 structuredContent 通过 outputSchema 校验
  • 把 resultFetched 改名后契约测试失败
  • 现有 mod 测试与 node 测试不改断言仍通过
02

派发与集成的步骤写在工具层

派发要按取锁、对账、策略、快照、worktree、建记录、启动 worker 的顺序进行，失败还要清理；这些只写在 relay_dispatch 处理函数里，apply 也一样。

值得探索 · 依赖：进程内 · 业务影响：测试为了在进程内跑 worker 重抄了派发步骤（缺锁和清理），CLI 和不讲 MCP 的脚本无法派发；以后改派发顺序要同时记得改测试里的副本。

现状图据源码绘制 · 红笔为评审批注

图号02 / 现状批注3依据源码 6 处

派发的顺序与清理只存在于 MCP 处理函数，测试抄了一份不完整的副本，CLI 没有入口。

  1. ①
    顺序只在工具层已观察

    派发必须先取锁并对账存活，再做策略判定、取快照、建 worktree、建记录、启动 worker，建记录失败还要删掉 worktree；这些顺序和清理只写在 relay_dispatch 里。

  2. ②
    测试复制派发步骤已观察

    test/relay.test.mjs 的 prepareJob 为在进程内驱动 worker，重抄了策略、快照、排除、worktree、建记录，但没有派发锁和失败清理；派发顺序一改，副本就会悄悄过时。

  3. ③
    CLI 不能派发已观察

    CLI 只有 mcp、worker、doctor、status；不讲 MCP 的脚本或 CI 想派发任务，只能自己重写这套步骤。

调用方现在要记住：

  1. 先拿派发锁
  2. 先对账再判策略
  3. 快照后建 worktree
  4. 失败要删 worktree
  5. 最后启动 worker

收拢之后只剩：

  1. 调 dispatch()

方案
